# AgentRMC 桌宠交互（DeepSeek Harness）

通过本插件注册的四个工具操作本机 AgentRMC 桌宠。前提：AgentRMC 正在运行；
没运行时工具会返回友好错误，如实告知用户即可，不要重试。

## 四个工具

- **pet_notify**：桌宠冒一条气泡（不出声；桌宠收起时走系统托盘）。用于长任务
  的阶段进度（「正在跑测试，12/20」）、中途发现的重要信息。`event` 可选
  （如 `progress`），只影响事件流归类。
- **pet_speak**：桌宠说一句话——冒气泡并 TTS 朗读。用于最终结论、需要用户
  立刻注意的事。
- **pet_state**：查桌宠状态（可见/贴边收纳/监听/录音/转写/对话模式/TTS 就绪）。
  拿不准桌宠在不在、TTS 能不能出声时先查一眼再决定用哪个工具。
- **pet_work_update**：把任务阶段写进「待我处理」列表——`progress`（正在干）/
  `blocked`（卡住，等人）/ `ready`（做完，等验收）。`progress` 只更新工单不出声；
  `blocked` / `ready` 会冒气泡并语音提醒用户（要人动手的事必须喊到），所以阶段
  真的变了才报，别每跑一条命令都报一次。

## 提醒分工：插件自动提醒 vs 主动汇报

**等授权、等选方案（`ask_user_question`）、等你回话、任务完成这四类，插件在
弹窗/收尾那一刻自动提醒**——桌宠出声、把宿主窗口拉到前台、建待办卡。一律
不要用工具重发：

- 桌宠在你调用 `ask_user_question` 时**立刻**出声（插件监听的是提问之前的事件）。
  提问之前**不要**先 `pet_speak` 或 `pet_work_update stage=blocked` 打招呼——
  补了就是同一件事念两遍。
- 「等你回话」判的是回复**最后一句以问号收尾**：把要问的话写在回复末尾，
  **问号后面别再接任何正文**——破折号补充、客套话都会让判定失效，桌宠会把
  这轮念成「做完了」。这种轮次同样不用补 `pet_work_update stage=blocked`，
  两边都发就是念两遍。
- 模型出错没有单独的提醒事件：错误文本会作为最终回复被照常念出来。

**主动汇报只用在插件盖不到的时刻**：

- 长任务的阶段进度 → `pet_notify`（要人当场看见）或 `pet_work_update
  stage=progress`（留在「待我处理」列表里）。
- 回合还没结束就先卡住（缺凭据、外部服务挂了）→ `pet_work_update
  stage=blocked`，它自己会出声；再补一条 pet_notify 就是同一件事说两遍。
- 最终结论、需要用户立刻注意的事 → `pet_speak`。

## 礼仪

- 一句话以内；长内容用户来不及看，也念不完。
- 一次任务最多几条提示，别连续调用刷屏；进度更新走 pet_notify /
  pet_work_update，收尾才用 pet_speak。
